01 / Why this project

From a local feature demonstration to verifiable network evidence.

Functional correctness alone does not explain the deployed request path or behavior under concurrent access.

Problem

Function alone does not explain network behavior.

R Mall creates repeatable read, authentication, and transaction requests that can be deployed, observed, and measured.

Objective 01

Develop

Design and develop a cloud-based small e-commerce platform that supports core online shopping functions.

Objective 02

Analyse

Implement and analyse the network communication mechanisms used by the platform in a cloud environment.

Objective 03

Evaluate

Evaluate the network performance of the deployed platform under different test parameters using Apache JMeter.

02 / Methodology

Iterative development, followed by controlled evaluation.

Each increment was implemented, verified, and documented before the next layer was added.

  1. 01Requirements

    Define scope, users, network focus, and measurable objectives.

  2. 02Development

    Implement storefront, authentication, cart, orders, and administration.

  3. 03Cloud deployment

    Serve the frontend through Nginx and route API traffic to Spring Boot.

  4. 04Verification

    Check functional, integration, deployment, and database behavior.

  5. 05Performance tests

    Run controlled Apache JMeter scenarios and retain measurable results.

04 / Performance evidence

Tested journeys remained executable, while several high-load scenarios recorded multi-second P90 response times.

The Chapter 4 evidence covers smoke, read-only, authenticated, and controlled mutation scenarios.

What the evidence shows

The planned journeys completed without observed JMeter errors.

Read-only scenarios reached 200 threads, authenticated scenarios reached 100 threads, and controlled mutation scenarios reached 10 threads in the stated ramp-up patterns.

What the evidence also shows

Higher-load browsing produced multi-second P90 response times.

Future work can evaluate caching, asset optimization, query tuning, HTTPS deployment, and additional capacity when the project scope expands.

Evidence source: Chapter 4, Tables 4.17 and 4.18, supported by retained aggregate results, summary tables, execution record, and performance evaluation report dated 16 June 2026.
