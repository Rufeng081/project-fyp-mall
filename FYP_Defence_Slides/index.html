06 / 12

Critical implementation decisions

Three integration problems defined the deployed system.

01

Problem

Local paths broke in production

Decision

Nginx owns the public entry point; /api is proxied internally and SPA routes fall back safely.

Verified outcome

One consistent public request path
02

Problem

Authentication needed short-lived state

Decision

Redis stores verification codes, five-minute TTL, cooldown keys and session records.

Verified outcome

Repeatable account recovery and access
03

Problem

Uploaded media paths were not stable after deployment.

Decision

A persistent upload directory and explicit Nginx resource routing separate data from builds.

Verified outcome

Stable public product and avatar images

Performance evaluation

After smoke validation, eight scenarios were tested in three controlled workload groups.

Apache JMeter first verified each scenario with smoke testing, then repeated the public HTTP journeys using controlled thread, ramp-up and loop parameters.

Highest tested200threads

Read-only

  • Homepage
  • Product list
  • Product detail
Highest tested100threads

Authenticated

  • Login
  • Order history
Highest tested10threads

Controlled mutation

  • Add to cart
  • Place order
  • Simulated payment

Why only 10 mutation threads? These requests change live stock, cart and order data, so the workload was deliberately bounded to protect repeatability.
